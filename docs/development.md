# Container-Based Development Checks

These workflows require Docker, not a host Python or uv installation. They use
the Dockerfile's builder stage as a disposable tools container; the production
image remains minimal and does not contain tests or maintenance dependencies.
Run commands from the repository root.

## Offline Tests

```sh
docker build --target builder -t rigol-mcp:tools .
docker run --rm \
  --mount "type=bind,src=$PWD,dst=/work,readonly" \
  -w /work -e UV_PROJECT_ENVIRONMENT=/tmp/rigol-venv \
  --entrypoint uv rigol-mcp:tools \
  run --python /usr/local/bin/python --locked --extra test pytest -p no:cacheprovider
```

The tools container downloads locked test dependencies into its temporary
environment. Tests themselves use fake instruments and do not contact the scope.
The source mount is read-only; temporary test files stay inside the container.

## Image Smoke Tests

CI runs the image tests automatically. To run them locally without host Python,
build the runtime image and use Docker CLI from a test container:

```sh
docker build -t rigol-mcp:local .
docker run --rm \
  --mount "type=bind,src=$PWD,dst=/work,readonly" \
  --mount type=bind,src=/var/run/docker.sock,dst=/var/run/docker.sock \
  -w /work -e UV_PROJECT_ENVIRONMENT=/tmp/rigol-venv \
  -e RIGOL_TEST_IMAGE=rigol-mcp:local \
  --entrypoint sh rigol-mcp:tools -c \
  'apk add --no-cache docker-cli && uv run --python /usr/local/bin/python --locked --extra test pytest tests/test_container.py -p no:cacheprovider'
```

This assumes the local Docker daemon exposes `/var/run/docker.sock`; other
contexts may require a different endpoint. **Socket access grants control over
the Docker host.** Use this only with trusted source code, or rely on CI instead.
Do not give the production MCP container access to the Docker socket. The image
tests launch isolated, network-disabled containers and never query hardware.

## Reference Audit

Download the official programming guide separately into a local directory.
Set `REFERENCE_DIR` to its absolute path and use the actual PDF filename below:

```sh
export REFERENCE_DIR=/absolute/path/to/reference-files
docker run --rm \
  --mount "type=bind,src=$PWD,dst=/work,readonly" \
  --mount "type=bind,src=$REFERENCE_DIR,dst=/reference,readonly" \
  -w /work -e UV_PROJECT_ENVIRONMENT=/tmp/rigol-venv \
  --entrypoint uv rigol-mcp:tools \
  run --python /usr/local/bin/python --locked --extra catalog python -m tools.check_capability_reference \
  /reference/DHO800900_ProgrammingGuide_EN.pdf
```

The audit reads the pinned PDF and fails on checksum or catalog drift. It does
not change artifacts or fetch reference documents automatically.

For candidate extraction, prepare an output directory and mount it separately:

```sh
mkdir -p captures/reference-review
docker run --rm \
  --mount "type=bind,src=$PWD,dst=/work,readonly" \
  --mount "type=bind,src=$REFERENCE_DIR,dst=/reference,readonly" \
  --mount "type=bind,src=$PWD/captures/reference-review,dst=/output" \
  -w /work -e UV_PROJECT_ENVIRONMENT=/tmp/rigol-venv \
  --entrypoint uv rigol-mcp:tools \
  run --python /usr/local/bin/python --locked --extra catalog python tools/build_scpi_catalog.py \
  /reference/candidate-guide.pdf /output/candidate-commands.json
```

Review the candidate against the shipped data before updating it. See the
[reference review procedure](dho814-support.md#reference-review).

## Live Smoke Test

Only run this on an idle scope without a connected device under test. Stop the
registered MCP server first so there is no second connection to the instrument.
The test starts a server inside the tools container, temporarily changes settings,
and attempts to restore them; do not interrupt restoration.

```sh
mkdir -p captures screenshots
docker run --rm \
  --mount "type=bind,src=$PWD,dst=/work,readonly" \
  --mount "type=bind,src=$PWD/captures,dst=/work/captures" \
  --mount "type=bind,src=$PWD/screenshots,dst=/work/screenshots" \
  -w /work -e UV_PROJECT_ENVIRONMENT=/tmp/rigol-venv \
  --entrypoint uv rigol-mcp:tools \
  run --python /usr/local/bin/python --locked python tools/test_live_scope.py --ip 192.168.1.43
```

Replace the IP with the intended scope's address. This diagnostic harness uses
`--ip` and passes it to its server subprocess as `RIGOL_IP`; normal MCP operation
uses the runtime environment variable directly. The report and captures are
written to the mounted host directories. Files generated by tools containers may
be root-owned on Linux. Restart the registered MCP server after the test exits.
